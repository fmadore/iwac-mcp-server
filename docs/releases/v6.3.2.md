# v6.3.2: a lighter chart view, corrected guidance and a tidier deployment

A patch release of the remaining findings from the v6.2.0 review (#74, #79,
#80, #81, and most of #82), plus an in-range security update. No tool or
argument is added or removed. The always-on footprint goes from 15,723 to 15,708
of 16,000 tokens.

## A lighter chart view (#74)

The chart view's decoded script went from 497.7 KB to 382.9 KB of its 500 KB
limit, which leaves room for the next views and SDK updates. The build now drops
MCP client code the view never runs (OAuth, the client itself, a Cloudflare
Workers validator) and two zod modules nothing calls, which are replaced by stubs
that fail loudly if anything ever reaches them.

## Corrected guidance for models (#79)

The `iwac-mcp` skill, served to connected models over `skill://`, and the
server's prompts carried some wrong contracts and facts older than v6.0.0.

- `search_by_sentiment` takes no date filter; `search_articles`' `subject` must
  match a whole tag; at month granularity, year-only dates go to
  `imprecise_date_count`; `list_locations(country="Nigeria")` returns the entries
  its references and audiovisual records mention.
- The copy-paste disclosure paragraph names all six sentiment models and the
  current 30% unanimity figure. The inline sentiment default is
  `claude-haiku-5-5`, and the newest ~4,400 articles carry its single vote rather
  than no sentiment.
- The skill counts 39 tools and four semantic search tools, lists photographs
  among seven kinds of material, and gives current index and reference counts.
- The research prompt names only the chart tools a server actually registers,
  so a restricted tool profile no longer advertises missing tools.

## HTTP (#80)

- The SDK now reads request bodies itself, with the same 4 MiB cap. A non-JSON
  body sent with a non-JSON content type is answered 415 rather than 400.
- The two chart resources are cached privately, since their sandbox domain
  follows the URL a client connected through; the resource template list is
  cacheable for an hour.

## CI and deployment (#81)

- A push to `main` can no longer cancel the weekly dataset-drift check, and the
  README version check accepts pre-release versions.
- The HTTP server pre-downloads the query encoder only when a semantic search
  tool is registered.
- The Docker image no longer installs the packages already built into the server
  file (the MCP SDK and its HTTP server, zod, the tokenizer) and keeps only the
  onnxruntime binary for its own architecture.

## Housekeeping (#82)

- Every year grouping and year filter reads source dates the same way. A range
  such as "1995/1997" now matches a 1996 filter, and a date that does not parse
  is undated instead of being grouped under its first four characters.
- Streaming query results are always closed, timestamp offsets such as `+01`
  parse, the French-language readability check ignores accents, and semantic
  queries advertise their real 2,000-character limit. Unused fields and exports
  are removed.
- The retrieval evaluation script runs on Windows and covers references;
  outdated documentation is corrected.

## Security

An in-range lockfile update fixes moderate advisories in `hono` and
`@hono/node-server`, which the MCP SDK brings into the server file. `node-forge`
now resolves to a patched version, so its exception is lifted; the only open
advisory is in a zod copy inside the development-only packaging tool, which never
ships (see SECURITY.md).
