# v4.2.0: The skill is served by the MCP SDK

The server has carried the `iwac-mcp` research skill since v3, as `skill://`
resources and through the Skills extension (SEP-2640), using its own handlers.
MCP TypeScript SDK 2.4.0 ships that extension, so this release hands the
protocol over to the SDK and keeps only what the SDK does not do
([#54](https://github.com/fmadore/iwac-mcp-server/issues/54)).

- **SDK 2.4.0.** `@modelcontextprotocol/server` and `client` move to 2.4.0 and
  `@modelcontextprotocol/node` to 2.1.2. The server and client are pinned to
  the 2.4 minor (`~2.4.0`), because the SDK marks the extension's `attach()` as
  experimental and may rewire it in a minor release.
- **The SDK builds and serves the skill.** It computes each file's size and
  SHA-256 digest, checks the frontmatter and publication limits, and serves
  `skills/list`, `skills/get` and the `skill://{+path}` template. The bundler
  loads the skill through the same SDK code under `strict`, so a malformed skill
  fails the build instead of shipping.
- **Directory reads.** The server now advertises `directoryRead` and answers
  `resources/directory/read`. As a result `skill://iwac-mcp` is the skill's
  directory. **This changes one URI:** it used to return a JSON catalogue of the
  files with their digests. `skills/list` carries the same manifest.
- **Every file stays listed.** The SDK's own catalogue puts one entry per skill
  in `resources/list`. Hosts without the extension (Claude Desktop, Claude Code)
  find the reference files there, and SKILL.md names them by relative path, so
  the server keeps listing all five files with a title and a one-line summary.
- **Verified from the client side.** `test/skills.test.mjs` now reads the skill
  through the SDK's `SkillsClient`, which checks every file against the
  manifest, and still compares each file byte for byte with the source on disk.
- **Dependency hygiene.** `@modelcontextprotocol/node` 2.1.2 accepts
  `@hono/node-server` 2.x, so the `overrides` entry that forced it is gone; npm
  still resolves 2.1.3. `hono` moves to 4.13.14, which clears a `serveStatic`
  advisory (the server never used `serveStatic`).

No tool, prompt or data behaviour changes.
