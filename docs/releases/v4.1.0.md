# v4.1.0: Similar items match the published list

The IWAC dataset publishes each article's and document's ten nearest neighbours
as `related_articles`, and the "Similar articles" panels on islam.zmo.de have
shown that list since IwacVisualizations v1.79.0. `get_similar_items` used to
recompute the ranking on every call. It ranked by the same rule, so the two
agreed on 16,707 of 16,715 articles; the other 8 differed only in the order of
two neighbours whose scores tie at four decimals. This release reads the
published list, so the server and the site return the same neighbours by
construction ([#49](https://github.com/fmadore/iwac-mcp-server/issues/49)).

- **Published list first.** For articles and documents the neighbours start
  with the stored list, in its stored order and with its stored scores. A
  researcher quoting "the ten closest articles" now quotes the list the dataset
  publishes for that revision, which is also the revision the provenance block
  names.
- **Live past ten.** The default `limit` stays 12. Neighbours beyond the stored
  list are ranked live, skipping the listed ones, and are not re-sorted against
  them: across that seam a live score can sit above a stored one.
  `stored_count` says where the seam falls.
- **The output says which ranking it used.** `neighbours_source` is
  `related_articles`, `related_articles+live` or `live`, and the note says the
  same in words.
- **Live fallback.** Publications and references publish no list, and upstream
  empties the whole column whenever a vector or the set of rows changes until
  it is recomputed. Those cases, and any revision without the column, rank live
  as before. A listed id missing from the snapshot is dropped and reported in
  the note.
- **Faster when the list suffices.** With `limit` at 10 or below, a call reads
  one row and the metadata of ten ids instead of scanning all 16,668 article
  vectors: about 60 ms per call through the server against about 610 ms on the
  development laptop. The default `limit` of 12 still needs the scan for its
  last two neighbours.

Checked against the real dataset (revision `d834ab71`): for 12 sampled
articles, `limit` 10 returned each `related_articles` cell exactly, ids and
scores, and `limit` 12 returned the same ten followed by two live neighbours.

Document → article neighbours remain out of scope: neither the dataset nor this
server publishes a cross-subset ranking.
