# v3.7.0

This release repairs semantic search in the Claude Desktop extension, cuts the
extension's download by a third to a half, keeps the server's data current
without a restart, and makes it faster and its answers reproducible. Tool
names, input/output schemas and registration order are unchanged.

- **Semantic search works again in the desktop extension.** The bundles for
  v3.6.0 and earlier lacked the Google authentication code that the Gemini
  client loads, so `semantic_search_*` failed at start-up in Claude Desktop.
  A packaging rule meant for this project's own `src/` folder also matched
  `build/src/` inside two dependencies. The hosted endpoint and Docker image
  were not affected. Each bundle is now unpacked and its runtime packages
  loaded as part of the release, so a broken bundle cannot ship.
- **Smaller downloads.** The bundles no longer carry the development
  toolchain, which included Linux-only Biome and TypeScript binaries. macOS
  goes from 112 MB to 70.5 MB and Windows from 69 MB to 29.4 MB, and the
  install unpacks roughly 100 MB less.

- **Background dataset refresh.** A loaded subset is re-checked against
  Hugging Face every `IWAC_REFRESH_HOURS` (default 24; `0` turns it off). A
  newer revision is downloaded beside the files in use and swapped in with a
  single view change, so a query already running finishes on the old data. The
  replaced files are pruned afterwards. A failed check keeps the data already
  loaded. Existing caches stay valid, so upgrading downloads nothing.
- **Concurrent queries.** Each DuckDB query now gets its own connection
  instead of queuing on one shared connection. One caller's full-text scan no
  longer stalls everyone else's requests, and fan-outs such as `search` and
  `get_collection_stats` run in parallel. Stats tools, pagination and the
  five-model sentiment breakdown run their independent queries together.
  Semantic search overlaps the Gemini call with its index load and prefilter.
- **Cheaper HTTP requests.** Tool registrations and their JSON Schemas are
  built once per process, not once per request. Building a server dropped
  from 13.2 ms to 0.9 ms, and `tools/list` from 24.9 ms to 9.2 ms.
- **Deterministic results.** Rankings with tied counts, and distributions with
  no explicit order, came back in a different order from run to run. Where a
  limit applied, the items returned could change as well. Every ranking now
  has a stable tie-break.
- **Safer downloads.** Each download is checked against the size and SHA-256
  that Hugging Face lists before it replaces anything in the cache. A truncated
  or corrupted transfer is discarded and retried rather than served.
- **Bounded concurrency.** At most 16 queries run at once, and the rest wait
  their turn, so a burst cannot run every caller's full-text scan together.
- **Clean shutdown.** On SIGTERM the HTTP server finishes the requests already
  in flight (for up to 8 s) before exiting. It no longer cuts them off on
  every `docker stop` or redeploy.
- **Fixes.** Keyword excerpts no longer drift off their match when the text
  contains a dotted capital I (İ). Truncated text, excerpts and chart titles
  no longer split an emoji into a stray escape code. The server no longer
  advertises `listChanged` for lists that never change, so 2026-07-28 clients
  do not hold idle notification streams open.
- **Dependencies.** MCP TypeScript SDK 2.1.0 (server, node, client). The
  refreshed lockfile clears the `hono` advisory, and npm audit reports zero
  vulnerabilities.

The detailed implementation and verification history is in `REFACTORING.md`.

Validation: typecheck, lint, build, 124 unit tests, three lifecycle tests, and
all fixture, chart, skill, HTTP and token-budget checks pass on Node 24 and on
the Node 20 runtime floor. The tool-definition token footprint is unchanged.
The live smoke test against the Hugging Face dataset was not run for this
release. The weekly CI run covers it.
