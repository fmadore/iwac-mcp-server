# v6.2.0: IWAC opens in Claude, and Claude works in the chart

A minor release for Claude's full-screen apps, launched on 10 November 2026.
Tool names, arguments and result shapes are unchanged. The one change a model
sees in `tools/list` is a marker on `get_collection_stats` (+15 tokens; the
always-on footprint is 15,723 of 16,000).

These features reach Claude through the hosted endpoint
(`https://islam.zmo.de/mcp/`) as a custom connector. Claude is rolling some of
them out to organisations gradually, so not every account shows them yet. The
local Claude Desktop extension is unchanged.

## Claude can work in the open chart

The chart view registers four tools of its own, which Claude lists while the
view is open and asks before using:

- `describe_view` reads the selection on screen, the buttons Claude may press
  and the chart marks it may open.
- `run_view_action` presses a button, such as Back, "Read source items" or a
  display option.
- `open_chart_mark` opens the drill-down behind a bar, cell, country or point,
  as a click would.
- `show_result` loads another IWAC chart into the same view, where Back still
  returns to the previous selection.

They act only through what a person can do in the view, and each returns the
new selection summary or the error the view showed. Claude cannot use them to
send a chat message, switch the display mode, download a file or open a link.
They live in the view, so they add nothing to the always-on footprint.

## Open IWAC without a prompt

`get_collection_stats` is marked as an entry point, so the collection overview
appears on Claude's Artifacts page and can be pinned to the sidebar. Opening it
starts a conversation with the overview on screen; each subset is a drill-down.
The server now declares an icon (`serverInfo.icons`, a 128 px inline JPEG) for
the tile and for the title bar of a side-panel or full-screen view.

## Charts in the side panel and full screen

- **A stable sandbox host.** Over HTTP the chart resources declare Claude's
  `_meta.ui.domain`, so the view keeps the same origin from one conversation to
  the next. Claude derives that host from the connector URL exactly as typed
  and refuses to draw a view whose value does not match. Because the endpoint
  answers both `/mcp` and `/mcp/`, the value is worked out for each request
  from `IWAC_MCP_PUBLIC_URL` and the request's own trailing slash. The new
  `IWAC_MCP_UI_DOMAIN=false` leaves it out. stdio never sets it.
- **The semantic map asks for full screen.** `get_semantic_map` now opens
  `ui://iwac/charts-wide.html`, the same document with Claude's
  `preferredDisplayMode: "fullscreen"` hint. The other charts keep opening in
  the conversation.
- **Checked at side-panel width.** Every chart is now tested at 320 px in the
  mode Claude uses for its side panel, with no horizontal scrolling.

## Not in this release

Embedded sites (framing islam.zmo.de pages inside the view) would need a
header change on the archive and, for a custom connector, are limited to some
organisations. App-only server tools are not needed yet: every call the view
makes goes to a tool the model already has.

## Internals

- The decoded chart script is 496.1 KB of its 500 KB gate.
- The WebMCP bridge stays off. The view's tools reach Claude over the MCP Apps
  channel, which does not need it, and a tool planted in `document.modelContext`
  still never reaches `tools/list`.
- New tests cover the view tools, the entry point and icon, the full-screen
  resource, the per-request domain for both URL forms, and the 320 px layout.
