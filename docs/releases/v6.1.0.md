# v6.1.0: browser access, a sandboxed query engine and a Server Card

A minor release. Tool names, arguments and result shapes are unchanged. Sentences in
eight tool descriptions are reworded (see below), which is the one
thing an existing caller's model will read differently.

## Reaching the server from a browser

- **CORS on the HTTP transport.** A request from an allowlisted or loopback
  origin was accepted but answered without `Access-Control-Allow-Origin`, and
  its preflight got a 401, so no browser client (MCP Inspector, MCPJam, an
  in-page app) could use the endpoint. `/mcp` now answers the preflight before
  the bearer check and sends the CORS headers on every response.
- **`IWAC_MCP_ALLOWED_ORIGINS=*`** is an explicit opt-in for public
  deployments. It is accepted only as the whole value, and the server refuses
  to start with it when it serves the private mirror.
- **MCP Server Card** (SEP-2127). `GET /mcp/server-card` returns the server's
  identity without a token. Set `IWAC_MCP_PUBLIC_URL` to the public endpoint
  and the card also lists the remote and its protocol versions.

## Hardening

- **DuckDB runs sandboxed.** File access is limited to the dataset cache and a
  spill directory inside it, extension loading is off, and the configuration is
  locked. Every user value was already bound as a parameter; this bounds what a
  future SQL-building mistake could read.
- **Spilling works in the container.** The spill directory used to default to
  `.tmp` under the working directory, which the image's `node` user cannot
  write. `IWAC_DUCKDB_MEMORY_LIMIT` and `IWAC_DUCKDB_THREADS` are new and
  optional.
- **A first call during the dataset download says so.** A call cut off by the
  120 s limit while a subset is still downloading now returns an `unavailable`
  error naming what is loading and asking to retry, instead of a raw abort. A
  client that sends a progress token receives download progress (stdio hosts;
  the HTTP transport's JSON mode drops mid-call notifications).
- `/metrics` reports a `failed` count, and the image health check follows
  `PORT`.

## Charts

- The view declares the display modes it supports, and offers "Exit
  fullscreen" only when it entered fullscreen itself (Claude reports its side
  panel as fullscreen).
- A pending state names what is being computed while a tool runs.
- Safe-area insets and the host's container height are respected, and the
  charts stay legible in Windows high-contrast mode.
- `@modelcontextprotocol/ext-apps` moves to 2.1.0 with the WebMCP bridge off,
  since the view registers no tools of its own.

## Tool descriptions

Descriptions now state facts about the data rather than tell the model what to
do, as Anthropic's connector review criteria ask. `search_articles`, for
example, says "The press is French; English terms match only the English
abstract" where it said to use French keywords whatever the user's language.
Eight tools are affected: `search`, `search_articles`, `search_publications`,
`search_documents`, `get_collection_stats`, `search_by_sentiment`,
`get_sentiment_distribution` and `get_lexical_metrics`. The always-on footprint is 15,708 tokens (15,717 before).

## Fixes

- The extension's long description listed five sentiment models; it now lists
  the six that v6.0.0 serves, with `claude-haiku-5-5` as the default.
- `IWAC_MCP_ALLOWED_ORIGINS` no longer accepts `https://*.example` as a literal
  host.

## Internals

- TypeScript runs with `noUncheckedIndexedAccess`, `noUnusedLocals`,
  `noUnusedParameters`, `noImplicitOverride`, `noFallthroughCasesInSwitch` and
  `verbatimModuleSyntax`. The pass found no defect.
- Chart views receive typed payloads through one registry; the casts are gone.
- The three largest test files are split by domain with identical checks, and
  the MCP conformance suite now gates CI.
